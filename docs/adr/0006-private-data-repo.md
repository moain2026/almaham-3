# 0006 — مستودع خاص للبيانات: `moain2026/almaham-3-private-data`

## السياق والمشكلة
- ADR-0004 يمنع صور العملاء في هذا المستودع **العام** (`/data/`, `**/photos/` في `.gitignore`).
- النتيجة العملية في 2026-10-18/20: المالك رفع الصور إلى الفرع فرفضها git **بصمت** ولم تُحفظ؛ و3,014 صورة ERP منزَّلة + 11 GB بيانات اصطناعية + `data/review/` **ضاعت كلها** مع إغلاق السندبوكسات. الوكيل الخليفة بدأ من بيئة بلا صورة واحدة ولا يستطيع حتى إعادة إنتاج 19/46.
- قاعدة المالك: «كل شيء يُرفع، كل شيء موثّق ومحفوظ».

## الخيارات
1. تحويل `almaham-3` إلى خاص ورفع الصور فيه — يخلط كوداً عاماً (رخص، إصدارات APK منشورة) ببيانات عملاء؛ ويكبّر المستودع لعدة GB.
2. Git LFS في المستودع العام — الصور تبقى قابلة للتنزيل علناً عبر LFS؛ حصة LFS محدودة.
3. **مستودع خاص منفصل** للبيانات + سكربت جسر في العام (`scripts/private_data.sh`) + روابط رمزية إلى `data/`.
4. تخزين خارجي (Drive/S3) — ليس تحت git، لا تاريخ، يحتاج بيانات دخول إضافية.

## القرار
**الخيار 3.** أُنشئ `moain2026/almaham-3-private-data` (private=true) في 2026-10-20 بالتوكن الذي أعطاه المالك.
- الهيكل والقواعد في README المستودع الخاص؛ كل رفع يُسجَّل في `MANIFEST.md` هناك وسطر في `STATUS.md` هنا.
- في أي بيئة جديدة: `bash scripts/private_data.sh pull` ⇒ يسحب ويربط `data/photos` و`data/erp/photos` ويشغّل `verify_photos.sh`.
- الرفع: `push-49 <zip|dir>` (يتحقق من sha256 الرسمي قبل القبول)، `push-erp` (دفعات ≤1.5 GB)، `push-dir` لأي مجلد ثقيل (أوزان وسيطة، سجلات، نتائج مراجعة، قياسات الجوال).
- **يبقى ADR-0004 سارياً** على هذا المستودع العام: لا صورة عميل هنا أبداً. المستودع الخاص هو المكان الوحيد.
- البيانات الاصطناعية الكاملة (11 GB) لا تُرفع؛ تُعاد توليدها ببذور ثابتة (`gen_det_data.py`). تُرفع عيّنات صغيرة فقط.

## العواقب
✔ لا يضيع شيء بعد اليوم؛ بيئة جديدة تعود للعمل الكامل بأمرين. ✔ تاريخ git للبيانات (من أضاف ماذا ومتى). ✔ التوكن الواحد يكفي للمستودعين.
✘ حجم المستودع الخاص سيصل لعدة GB (حدود GitHub: ملف ≤100 MB، push ≤2 GB — السكربت يقسّم). ✘ على المالك ألا يجعله عاماً أبداً، وأن يعطي الوكلاء توكناً بصلاحية `repo` فقط.
