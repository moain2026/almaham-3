## 2. التثبيت والتجربة على جوال حقيقي
> **تحديث 0.1.1 (وكيل B):** ثبّت **`almaham-meter-0.1.1-arm64.apk`** من GitHub Release `v0.1.1` (جوالات 64-bit فقط، 37,849,126 B):
> `adb install -r almaham-meter-0.1.1-arm64.apk`. نسخة bench (مع ML Kit للاختبار الجماعي) تُبنى محلياً: `./gradlew :demo:assembleBenchRelease`. التفاصيل: `docs/apk-size-report.md`.

```bash
adb install -r demo-debug.apk
# تجربة يدوية: افتح التطبيق ← «التقاط» ← وجّه المستطيل على شاشة العداد ← اضغط.
# الاختبار الجماعي على الـ49 صورة:
adb push data/photos/ /sdcard/Android/data/com.almaham.meterdemo/files/photos/
adb shell am start -n com.almaham.meterdemo/.MainActivity --ez autobench true
adb pull /sdcard/Android/data/com.almaham.meterdemo/files/  ./phone_results/
# المخرجات: bench_<device>.csv (سطر لكل صورة×وضع×محرك)، bench_summary_<device>.json، captures_log.csv، rectcheck/
```
ضع المخرجات في `benchmark/results/phone/` وادفعها.

## 4. المسار إلى ≥95% (ما ينقص بالضبط)
1. **المحدِّد:** تدريب locator_t جارٍ عند وكيل التدريب (يدفع كل 2000 خطوة؛ `docs/training-log-agentT.md`). يُدمج حين يتجاوز 20/46.
2. **تسميات حقيقية من الـ ERP:** 1711 سطر تسمية حتى الآن (`benchmark/data/erp/labels_*.csv`؛ وكلاء التسمية مستمرون حتى 1600 لكل شريحة). **تحذير وكيل B صحيح:** هذه تسميات بنموذج رؤية لا بشرية — قبل التدريب عليها: مراجعة بشرية لعيّنة ≥10%، وقبول الإجماع فقط.
3. **ضبط دقيق على الحقيقي:** `lab/erp_finetune.py build` ثم `train` (50/50 حقيقي/اصطناعي) — جاهز، لم يُشغَّل بعد (ينتظر الصور المحلية: 1313/ 1600+).
4. **القارئ v2:** أُوقف (val 39/97 أسوأ من نقطة البداية 45/97 — معدل التعلّم 5e-4 عند الاستئناف كان عالياً). لم يُصدَّر. السجل: `lab/logs/train_reader_v2_aborted.log`. يُعاد بـ lr 1e-4.
5. **قياس الجوال:** يحتاج جهازاً حقيقياً (§2). زر «استيراد الصور» (SAF) غير منفَّذ — بديل لو `adb push` لم يعمل.
