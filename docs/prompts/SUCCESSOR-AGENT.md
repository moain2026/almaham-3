## 4. أولوياتك بالترتيب (ولماذا)
1. **تأكد أنك تعيد إنتاج 19/46** قبل أي تغيير: `cd lab && bash eval_ckpt.sh weights/locator_t14500.pt weights/reader_ft4a.pt repro`. إن اختلف الرقم فابحث عن السبب قبل أي شيء.
2. **اختيار السطر بعد القراءة** (أكبر خطأ متبقٍّ ~8 صور): خذ أعلى 3 مرشحات من المحدِّد، اقرأ كل واحد، اختر من يعطي 6 خانات منتظمة بأعلى ثقة. نفّذه في `lab/assemble.py`/`eval_e2e.py` **ثم** مرآته في `ReadingAssembler.kt`/`MeterReader.kt` مع اختبار لكل منهما. قس قبل/بعد.
3. **الجولة ft5**: الأوامر الحرفية في `docs/PLAN.md` §3 و`train-digitnet.md` §4–5. ابدأ المحدِّد من `locator_t14500.pt`. lr 2e-4. اختر نقطة الحفظ بـ real_val لا بالـ49.
4. **مجموعة اختبار أكبر**: 300–500 صورة ERP بتسمية **بشرية** مجمّدة — 46 صورة = ±7% ضوضاء، لا يمكن إعلان 95% عليها.
5. **ادمج `lab/plausibility.py`** (T) في ألوان شاشة الإدخال (أصفر = غير معقول مقارنة بالقراءة السابقة؛ لا رفض).
6. **الجوال**: أرقام الزمن كلها CPU سيرفر. عندما يرسل المالك `captures_log.csv`/`bench_*` ضعها في `benchmark/results/phone/` واكتب p50/p95 الحقيقية في التقرير.
7. بعد كل تحسّن مقاس: انسخ ONNX إلى assets + MODEL_CARD + commit `model:` → `bash GenCode-APK/build.sh --convert` (يحوّل `.ort` ويوقف إن تغيّرت العوامل) → تطابق 49/49 → `--publish vX.Y.Z`.

## 5. قواعد لا تُكسر
- **الصور الـ49 للتقييم فقط.** لا تدريب عليها، لا ضبط عتبات عليها، لا اختيار نقطة حفظ بها. `erp_finetune.py build` يستبعدها بـ SHA256 تلقائياً — لا تعطّل ذلك.
- **لا صور عملاء في git** (`data/` متجاهل) ولا رفع لأي خدمة عامة. لا أسرار في الملفات أو رسائل الـ commit.
- **لا AGPL/GPL** (لا Ultralytics، لا نموذج الـ ERP القديم). رخصة كل مكوّن مذكورة في `docs/release-0.1.0.md` §6.
- **الجزء الصحيح فقط** من القراءة؛ الكسور لا تُقرأ أبداً. الأصفار البادئة تُحذف عند العرض.
- **لا gradle أثناء تدريب** في نفس الجهاز. `TORCH_THREADS=2` لكل تدريب. لا `git stash -u` أثناء تدريب (اقرأ السجل من `/proc/<pid>/fd/1` إن توقف).
- Python (`assemble.py`, `CONFIG`) وKotlin (`ReadingAssembler.kt`, `MeterOcrConfig.kt`) **مرآتان حرفيتان** — أي تغيير في أحدهما يُعكس في الآخر مع اختبار.
- **التوثيق جزء من العمل لا بعده:** سطر في `STATUS.md` بتوقيت لكل خطوة، `CHANGELOG.md`، `LESSONS.md` لكل خطأ، `docs/benchmark_report.md` لكل رقم، `docs/PLAN.md` عند تغيّر الخطة. commit بعد كل خطوة، `git pull --rebase` قبل كل push.
- **ممنوع تقريب الأرقام أو إخفاء نتيجة سيئة.** إن لم تصل لرقم اكتب الرقم الذي وصلت له وسببه.
